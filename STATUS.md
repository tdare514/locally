## What works
### Web (apps/web)
- Import mp3/wav/flac/m4a; non-mp3 converted to 320k mp3 via ffmpeg
- ID3v2 tagging, cover art with a square/original crop dialog
- Release edit in place: tracks are re-tagged, never renamed, so Spotify playlists keep the track
- Delete, reveal in Finder, settings
- Import and update requests validated with zod; every write checked inside the library dir
- Loopback-only server (127.0.0.1) with a full-origin CSRF check
- Sync client: email-code sign-in, push, reconcile, "From your devices" (an unknown release `origin` or device `platform` is read as "another device", never a failed page, #185); a cover replaced on either device follows via the record's coverHash (#26); each reconcile also pushes this Mac's play counts (every track whose count is ahead of what was pushed, at most 500 per request, failures left pending for the next reconcile), and the release page shows each track's total plays across devices ("12 plays", "1 play", no per-device split, nothing when no device has plays) with one line saying so, read once per page open from a local `GET /api/plays` (this Mac as the larger of its own and the service's count, plus the other devices; this Mac only when signed out or offline); sign-out, account deletion and a sync host change clear only the pushed markers, the counts stay local (#107)
- "From your devices" (was "From your phone", #185) lives in a top-right tray, not the sidebar (#115): a clear Liquid-Glass-style cloud button with an accent count badge becomes a bare red X while open (badge hidden); the frosted glass tray (a small backdrop blur, open only) drops out diagonally from its corner, opens and closes only from that button or Escape, shows each pending release as a small record sleeve that is itself the Send to Spotify button (hover: accent cover with a plus, the disc rolls out), with long titles and artists cut short so the tray stays slim, and a sent row collapses out; each row carries a quiet origin label ("from your iPhone", "from the web", "from another device")
- "Delete sync account…" in Settings deletes the cloud account after a confirm and signs this Mac out; music files stay (#34)
- Guided "Make it a playlist" disclosure on album release pages: Copy button for the title, per-track Mac steps and a fallback line; opens expanded on the page an album import lands on (#21)
- One-time "Spotify can't see this yet" prompt on the release page: copy path, open Spotify settings, dismiss; hidden once Spotify's local-files index lists the library folder
- Library is the home view: empty state mirrors iOS onboarding (diagram + Add your first single / Make an album); populated library splits Singles and Albums with counts in the main list (#7)
- Release page is an immersive editor (#112, web first): the cover's colours wash the pane, the cover is a record sleeve with a disc peeking out, title/artist/year/genre are inline fields under it, and saving tucks the record in and spins it out. Import still puts a 120 cover beside title and artist, then year and genre (#7)
- Library cover view (#112): a toggle in the library header switches between the list and a cover grid (still split into Singles and Albums) with a three-step cover size slider, both remembered; in both views a drifting, scroll-linked colour space fills the pane behind the library, coloured by the hovered cover or else the first cover on screen; covers lift on hover (the record stays on the release page); the column width is shared by both views and set in Settings (Comfortable 920px default, Full width 1240px)
- Sidebar (#154, replaces #116): a slim 64px rail is always there (logo, Library, Import with the fan-spin plus, Settings, a divider, the menu button) over the library colour space; hovering it (Open on hover, on by default) blooms a glass panel out of its right edge, the menu button opens it on click either way, Escape closes it and returns focus, it hides 300 ms after the pointer leaves, and Pin open docks it as a column that slides the pane over; Pinned, Open on hover and the chosen widgets are remembered in localStorage. The panel shows "On this Mac" (or the signed-in email, or Demo in the demo), rows for Library (with the release count), Import and Settings, then "Your plays" with Edit widgets: Top tracks, Top albums and Top artists (top three each, #1 larger with its cover) and an optional Stats shelf (three record sleeves, off by default), at least one on. The numbers are all-time totals on this Mac only, from one local request, `GET /api/plays/totals` (it reads `plays.json` and the library list and never asks the sync service; sent only when the panel opens, reused for a minute, retried once on the next open after a failure), ranked on the client in `src/lib/play-stats.ts`. Other devices' plays are not in them until #202 merges their days into the local summary (#200 adds `/api/plays/summary`, which this endpoint can fold into). With no plays (counting off, or the demo) a quiet line points to Settings; a failed read says "Couldn't load your plays". The Today / This week / This month control waits on per-day counts (`HAS_DAILY_COUNTS`, #193) and the Stats rail icon, row and "See all stats" on the Stats page (`HAS_STATS_PAGE`, #145), both in `src/components/sidebar/flags.ts`. The old Singles and Albums lists in the sidebar are gone; the library page has them
- Buttons (#155): one set across the Mac app, shown at `/dev/buttons` (dev only). Main actions (Save, Show in Finder, Sign in, Import to Spotify…) are just their label at rest and light up on hover into the phone-tray cloud button's glass with a mild glow of the cover's colour (a faint clear blue off covers) and one shimmer; secondary actions are underlined text with a soft white halo on hover, Delete the same in pink with a red halo (final confirms stay solid red); toggles (List/Grid, Single/Album, library width) are words with a dot under the chosen one
- Library search and sort (#7): a toolbar under "All music" filters by title, artist, genre, year, or track title (case- and accent-insensitive, every word must match; ⌘F focuses, Escape clears) and sorts by Recently updated, Title, Artist, or Year; both survive opening a release
- Library bulk actions (#7): Select on the library toolbar swaps in a selection bar; checked rows can be edited together (Artist, Year, Genre, blank leaves unchanged, tracks re-tagged in place) or deleted after an inline confirm. - Public read-only demo (#139): `LOCALLY_DEMO=1` (set only on the Vercel project `locally-web`, root `apps/web`, live at https://locally-web-liard.vercel.app and linked from the README with a screenshot) serves six invented releases with drawn SVG covers; the loopback Host check is skipped there, and every non-GET `/api/*` request answers 403 "Demo: read-only" from the proxy and again from each route; `getServices()` throws so nothing reaches the disk; the UI shows a Demo badge, disables import and edits, hides the phone tray and shows sync as an inert screen (SECURITY.md)
- Electron desktop shell (#35): `npm run desktop:package` produces an unsigned `dist-desktop/mac-arm64/Locally.app` that spawns the Next standalone server on a free 127.0.0.1 port (HOSTNAME forced, ADR 0003) and opens one locked-down window that, once closed, leaves the app running in the Dock (Dock click reopens it, ⌘Q quits; an "Open at Login" menu item starts it without a window, and one sync-status request at launch starts sync and play tracking with no window, #105); config lives in `~/Library/Application Support/Locally`, copied once from `~/.spotify-local-import` with owner-only modes; ffmpeg is a static LGPL 2.1 build (ffmpeg 9.0.2 + LAME 3.100, ADR 0006) built once by `npm run desktop:ffmpeg` from checksum-pinned sources and shipped as `Resources/ffmpeg` with the licence texts in `Resources/licenses`; arm64 only so far. Smoke: `LOCALLY_DESKTOP_SMOKE=1` with a `LOCALLY_DESKTOP_USER_DATA` temp dir. Interim updater (#78, ADR 0007): a launch check (at most every 6 h) and Locally ▸ Check for Updates… read an Ed25519-signed manifest from Blob, verify the zip's SHA-256, and swap the bundle with rollback after a prompt; `npm run desktop:publish` releases (see `apps/web/README.md`)

- Disc numbers (#113, plan `docs/plans/113-disc-number.md`): tracks carry an optional `discNumber` (1..99) in the model and sync record (API-validated; older clients ignore it); `trackNumber` stays the release-wide position and file key, and the tags get per-disc TRCK/trkn plus TPOS/disk only when discs are set; import reads disc tags and orders by disc; Disc 1 / Disc 2 headings show on the release page and import list when a release has more than one disc, and a dragged track takes the disc it lands in. ### Sync API (apps/api)
- Email-code accounts, device tokens, versioned releases (syncVersion 1 and 2) with last-writer-wins
- Quota enforcement and signed, expiring file URLs (local store and Vercel Blob)
- Rate limiting, CORS, daily cleanup cron
- Every response carries x-request-id; 4xx/5xx, rate-limit, quota and auth failures log one JSON line (request ID, route, status, duration, user ID); the daily cron logs total stored bytes, warning past STORAGE_ALERT_BYTES (#29)
- Device tokens expire after a year unused (the account itself never expires) (lastSeenAt refreshed at most daily); a cross-user test matrix shows another account gets 404 on every release, file and device route (#33)
- DELETE /v1/me deletes an account (email echoed as confirmation) in one transaction; its blobs are queued in pending_deletes and drained right after, with the daily cron as the guarantee (#34)
- Email send (`POST /v1/auth/code`) and release file prune (`PUT /v1/releases/:id`) run after the response via Next `after()`; blob deletes are batched with `FileStore.deleteMany` (#31)
- SQLite (libSQL) via Drizzle; migrated in the Vercel build in production, on first request in development and tests (#90)
- Release pulls are paged (#30): at most 200 releases or 2 MiB per `GET /v1/releases` page with `hasMore`; web and iOS loop until the last page, saving the cursor per page (100-page guard); `/v1/me` lists the 50 newest devices with `devicesHasMore`. Shipped clients stay correct and catch up over several reconciles
- Deployed to https://locally-sync-api.vercel.app (Vercel project locally-sync-api: Turso database, private Blob store, Resend); both clients default to it; smoke-tested end to end 28 Sep from a Mac and an iPhone 14: sign-in, push each way, tombstone (#3 closed). Resend still uses the sandbox sender, which only delivers to the owner's address: verify a domain and set MAIL_FROM before anyone else signs up (#58, `launch` label)
- Migrations run once per deploy in the Vercel build (`npm run db:migrate`, fails the deploy on error); each cold start only verifies the schema version. A redeploy of the current commit builds instead of being cancelled by the ignore step; pushes that don't touch apps/api are still skipped (#90)
- Play counts per device (#104, plan #102): `PUT /v1/plays` stores each device's absolute per-track count as max(stored, sent), ignoring entries for releases that aren't the user's live releases; `GET /v1/releases/:id/plays` returns per-track totals with every device (revoked ones too); account deletion removes plays and the daily cleanup removes plays of tombstoned releases. The Mac pushes to it and reads it (#107), the iPhone reads it (#108)
